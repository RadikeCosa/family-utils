# Publicación Champions Fase 1 · `champions-fase-1-rc2`

Guía de ejecución única. No contiene credenciales. Usar una copia limpia del tag. Este candidato excluye UFC 0037 e incluye las diez migraciones `0027`–`0036`: producción debe tener 27 migraciones antes y 37 después. `npm run db:migrate` y `npm run db:verify` leen **`DATABASE_URL_UNPOOLED`**; usar siempre la conexión directa de PostgreSQL, nunca el hostname agrupado/pooler. La aplicación web usa `DATABASE_URL`.

Cada paso es **manual**. Mantener `SPORTS_CHAMPIONS_ENABLED=false` en producción hasta el paso 10. El despliegue temporal del paso 7 usa `true` y comparte la base de producción; con el flag global de producción apagado, el switch que se encienda desde el temporal no habilita la vista pública de producción.

1. **manual — Opcional, ensayo con Neon; lo ejecuta el usuario.** Crear una rama Neon desde producción y restringir su acceso. En esa rama, con la conexión directa, ejecutar `DATABASE_URL_UNPOOLED="$NEON_BRANCH_DIRECT_URL" npm run db:migrate`, luego `DATABASE_URL_UNPOOLED="$NEON_BRANCH_DIRECT_URL" npm run db:verify`, y correr `psql "$NEON_BRANCH_DIRECT_URL" -v ON_ERROR_STOP=1 -f sources/champions/permisos-check.sql`. `ensayo-restauracion.sh` rechaza hosts remotos por diseño: antes de migrar la rama, hacer un dump de ella y restaurarlo en una copia **local** llamada `champions_test`; definir `LOCAL_RESTORE_URL` para esa copia y ejecutar `CHAMPIONS_RESTORE_DATABASE_URL="$LOCAL_RESTORE_URL" ./sources/champions/ensayo-restauracion.sh`. Comparar sus filas/hashes antes y después con la rama Neon. Borrar la rama Neon y verificar que desapareció. **Esperado:** ensayos y hashes sin diferencias no esperadas. **Revertir:** borrar la rama temporal; no se modificó producción. **NO SEGUIR SI:** la rama no nace de producción, hay diferencias no explicadas o no se puede comprobar su borrado.

2. **manual — Respaldo.** Con la URL **directa** de producción: comparar `pg_dump --version` con `SHOW server_version_num` en el servidor; `pg_dump` debe ser de versión igual o mayor que PostgreSQL servidor. Ejecutar `pg_dump --format=custom --no-owner --file=champions-pre-rc2.dump "$PROD_DATABASE_URL_UNPOOLED"`; comprobar `pg_restore --list champions-pre-rc2.dump` y restaurar una copia de prueba. **Esperado:** dump legible y restauración comprobada. **Revertir:** no se cambió producción; generar y validar otro dump si falla. **NO SEGUIR SI:** la versión de `pg_dump` es menor, o el dump/restauración falla.

3. **manual — Revisar el punto de partida.** Ejecutar `psql "$PROD_DATABASE_URL_UNPOOLED" -v ON_ERROR_STOP=1 -c 'SELECT count(*) FROM drizzle.__drizzle_migrations;'`. **Esperado:** `27`. Si da otro número, detenerse y comparar nombres/hashes con el journal hasta `0026`; no insertar ni marcar filas del journal manualmente. **Revertir:** no se cambió producción. **NO SEGUIR SI:** el conteo no es 27 o el inventario no coincide exactamente con migraciones hasta `0026`.

4. **manual — Aplicar y verificar migraciones.** Ejecutar desde la copia limpia del tag, siempre con conexión directa: `DATABASE_URL_UNPOOLED="$PROD_DATABASE_URL_UNPOOLED" npm run db:migrate`, y después `DATABASE_URL_UNPOOLED="$PROD_DATABASE_URL_UNPOOLED" npm run db:verify`. **Esperado:** diez migraciones nuevas (`0027`–`0036`), 37 aplicadas y hashes verificados. **Revertir:** no borrar migraciones; mantener Champions apagado y, ante fallo, recuperar el respaldo en una base de recuperación y corregir con una migración aditiva revisada. **NO SEGUIR SI:** falla una migración/hash o el total final no es 37.

5. **manual — Comprobar permisos antes de importar.** Ejecutar `psql "$PROD_DATABASE_URL_UNPOOLED" -v ON_ERROR_STOP=1 -f sources/champions/permisos-check.sql`. **Esperado:** lista todas las funciones de `public`; los permisos de `PUBLIC`, `anon` y `authenticated` son falsos. Si `anon` o `authenticated` no existen, el resultado indica `role_exists=false` y un NOTICE de que se omitió ese rol; no es un fallo. Si un permiso sale verdadero, para cada función indicada ejecutar manualmente `REVOKE EXECUTE ON FUNCTION public.nombre(argumentos) FROM PUBLIC;` y, solo para los roles presentes, `REVOKE EXECUTE ON FUNCTION public.nombre(argumentos) FROM anon;` y/o `... FROM authenticated;`; repetir el archivo. **Revertir:** no restaurar grants amplios. **NO SEGUIR SI:** queda algún permiso EXECUTE verdadero o el script termina con error.

6. **manual — Desplegar producción apagada.** Desplegar `champions-fase-1-rc2` con la configuración actual de Deportes/agenda y `SPORTS_CHAMPIONS_ENABLED=false`. No encender el switch familiar. **Esperado:** aplicación sana, River/UFC sin cambios y Champions bloqueado. **Revertir:** volver al despliegue anterior manteniendo el flag en `false`. **NO SEGUIR SI:** falla el health check, cambia River/UFC o alguna ruta permite acceso Champions.

7. **manual — Crear despliegue temporal protegido y habilitado.** Crear un Preview del mismo tag con protección de acceso para los operadores: exigir autenticación, limitar usuarios, y no permitir acceso público, alias abiertos ni crawlers. Configurar explícitamente: `DATABASE_URL` con el URL de la **base de producción** que usa la aplicación; `SPORTS_ENABLED=true`; `SPORTS_AGENDA_ENABLED=true`; `SPORTS_CHAMPIONS_ENABLED=true`; `BETTER_AUTH_URL` con el origen del Preview; `BETTER_AUTH_SECRET` y `CODE_PEPPER` con los secretos vigentes; `GOOGLE_CLIENT_ID` y `GOOGLE_CLIENT_SECRET` vigentes si se usan para iniciar sesión. Autorizar el callback OAuth del Preview de forma restringida. No ejecutar migraciones desde el Preview. **Esperado:** solo operadores autenticados pueden entrar; el Preview usa producción y Champions tiene flag global efectivo. El dominio de producción conserva `SPORTS_CHAMPIONS_ENABLED=false`. **Revertir:** eliminar Preview y cualquier acceso temporal. **NO SEGUIR SI:** la protección falla, la URL de base no es producción o el flag de producción deja de estar en `false`.

8. **manual — Encender el switch familiar e importar.** Desde la sesión administrativa protegida, encender el switch de la familia objetivo. Confirmar `effective=true` dentro del Preview. Revalidar los horarios en UEFA el día de la publicación; si el estreno es antes del 20/10, repetir la revisión la mañana del 19/10. En el JSON, guardar `checkedAt` con la hora real de la última verificación en UTC. Cargar `sources/champions/2026-27-jornada-3-agenda.borrador.json`, revisar la vista previa completa y confirmar con el token firmado recién emitido. **Esperado:** HTTP 200, primera carga `changed=true`, 18 partidos, 36 equipos y cero errores. **Revertir:** apagar el switch familiar, dejar el flag global de producción en `false`, corregir el archivo y volver a previsualizar tras revalidar la fuente. **NO SEGUIR SI:** el switch no está encendido en el Preview, falla la protección, UEFA cambió algún dato o hay cualquier error.

9. **manual — Verificar importación y privacidad.** Comprobar los 18 pares local/visitante, nueve partidos por día y horarios argentinos (cuatro a 13:45 y catorce a 16:00). Repetir vista previa y confirmación: `changed=false`, sin duplicados. En el Preview, un integrante guarda una elección de prueba; otro usuario, administrador, debe recibir `ownChoice=null` y `choices=[]` para esa elección. Borrar la elección de prueba antes del inicio. **Esperado:** 18 partidos/36 equipos, idempotencia, aislamiento por familia y ningún voto ajeno visible antes del cierre. **Revertir:** apagar switch y volver a corregir/importar solo después de revalidar. **NO SEGUIR SI:** cambian conteos, pares u horarios, se duplica información o el administrador ve la elección ajena.

10. **manual — Apagar el switch y habilitar el despliegue de producción.** Desde el Preview, apagar el switch familiar y verificar `effective=false` y conservación de datos. Solo entonces desplegar el mismo tag en producción con `SPORTS_CHAMPIONS_ENABLED=true`; mantener apagado el switch familiar. **Esperado:** Preview y producción bloquean Champions para esa familia; River/UFC siguen disponibles; la variable productiva pasa a `true` únicamente en este paso. **Revertir:** apagar el switch; desplegar producción con la variable en `false`. **NO SEGUIR SI:** hay acceso Champions con el switch apagado o se alteró River/UFC.

11. **manual — Retirar Preview y hacer pruebas de despliegue.** Eliminar el Preview, contraseña/excepción de acceso y alias temporal. Desde una sesión sin autenticar, comprobar que su URL ya no muestra la aplicación ni sus datos. En producción, con el switch familiar apagado, confirmar que Champions sigue bloqueado, que no acepta escrituras y que River/UFC funcionan. **Esperado:** no queda acceso temporal y la producción está lista, pero la familia permanece cerrada. **Revertir:** no reabrir el Preview públicamente; si se necesita repetir, crear uno protegido y retirarlo otra vez. **NO SEGUIR SI:** persiste acceso temporal, falla una prueba o el switch está encendido sin aprobación.

12. **manual — Apertura aprobada de la familia.** Solo con aprobación del operador, encender el switch de la familia en producción. Registrar en el ticket la hora de Argentina, el operador y el despliegue. Comprobar en el dominio público que la Jornada 3 y su hilo único aparecen y que los horarios son correctos. **Esperado:** Champions visible para la familia autorizada. Debe quedar hecho antes del **20/10/2026 13:45 (Argentina)**. **Revertir:** apagar inmediatamente el switch y comprobar que River/UFC siguen operativos. **NO SEGUIR SI:** falta la aprobación, la hora límite ya pasó o la jornada/hilo no se ven correctamente; en ese caso, no abrir y mover el estreno a Jornada 4.

Además, si el ensayo, la revalidación o los permisos no quedan listos antes del corte operativo **19/10/2026 18:00 (Argentina)**, no abrir Jornada 3: pasar el estreno a Jornada 4.
