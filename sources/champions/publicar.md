# Publicación Champions Fase 1 · `champions-fase-1-rc2`

Guía de ejecución única para producción. No contiene credenciales. Usar el URL de PostgreSQL de producción desde el gestor de secretos y ejecutar los comandos desde una copia limpia del tag. El candidato de este documento excluye UFC 0037: incluye las diez migraciones `0027`–`0036`; por eso el conteo esperado antes de migrar es 27 y después 37.

Cada paso es **manual**. Registrar hora, operador y resultado en el ticket de publicación. Mantener `SPORTS_CHAMPIONS_ENABLED=false` hasta el paso 7.

1. **manual — Respaldo.** Ejecutar `pg_dump --format=custom --no-owner --file=champions-pre-rc2.dump "$PROD_DATABASE_URL"` y comprobar `pg_restore --list champions-pre-rc2.dump` termina sin error. Restaurar una copia de prueba antes de continuar. **Esperado:** archivo legible y restauración comprobada. **Revertir:** no se cambió producción; si el respaldo no se puede restaurar, detenerse y generar uno válido. **NO SEGUIR SI:** falta el respaldo o no se verificó la restauración.

2. **manual — Revisar el punto de partida.** Ejecutar `psql "$PROD_DATABASE_URL" -v ON_ERROR_STOP=1 -c 'SELECT count(*) FROM drizzle.__drizzle_migrations;'`. **Esperado:** `27`. Si devuelve otro número, detenerse; comparar nombres y hashes con el journal de `champions-fase-1-rc2`, identificar migraciones ya aplicadas o faltantes y preparar un plan de reconciliación revisado antes de ejecutar ninguna. No insertar filas manualmente en el journal ni marcar migraciones como aplicadas sin verificar su SQL. **Revertir:** no se cambió producción. **NO SEGUIR SI:** el conteo no es 27 o el inventario no coincide exactamente con las migraciones hasta `0026`.

3. **manual — Aplicar migraciones.** Desde la copia limpia del tag y con el secreto cargado en el entorno, ejecutar `DATABASE_URL="$PROD_DATABASE_URL" npm run db:migrate`. Este candidato aplica `0027`–`0036`; no incluye `0037`. Luego verificar `DATABASE_URL="$PROD_DATABASE_URL" npm run db:verify`. **Esperado:** diez migraciones nuevas y 37 hashes aplicados verificados. **Revertir:** no borrar ni revertir migraciones; si falla, mantener Champions apagado, restaurar el respaldo en una base de recuperación y corregir con una migración aditiva revisada. **NO SEGUIR SI:** cualquier migración o hash falla, o el conteo final no es 37.

4. **manual — Comprobar permisos antes de importar.** Ejecutar `psql "$PROD_DATABASE_URL" -v ON_ERROR_STOP=1 -f sources/champions/permisos-check.sql`. **Esperado:** lista de todas las funciones de `public`; `PUBLIC`, `anon` y `authenticated` figuran sin EXECUTE y el script termina sin excepción. Si falla, copiar cada firma indicada y ejecutar una sentencia por función: `REVOKE EXECUTE ON FUNCTION public.nombre(argumentos) FROM PUBLIC, anon, authenticated;`. Si alguno de esos roles no existe, omitirlo solo después de comprobarlo en `pg_roles`. Volver a correr el archivo completo. **Revertir:** los REVOKE son restrictivos; no los reviertas para publicar. **NO SEGUIR SI:** el archivo no enumera todo `public`, devuelve permiso verdadero o no termina correctamente.

5. **manual — Desplegar apagado.** Desplegar el tag `champions-fase-1-rc2` con Deportes y agenda habilitados según la configuración ya vigente, pero `SPORTS_CHAMPIONS_ENABLED=false`. No activar el switch por familia. **Esperado:** aplicación sana; River y UFC responden como antes; Champions responde 404 y no permite escrituras. **Revertir:** volver al despliegue anterior manteniendo la bandera apagada. **NO SEGUIR SI:** falla el health check, cambia River/UFC o algún endpoint Champions permite leer/escribir.

6. **manual — Importar en despliegue temporal protegido.** Crear un despliegue temporal del mismo tag, autenticado y limitado a los operadores; bloquear acceso público, alias abiertos y crawlers. Usar `sources/champions/2026-27-jornada-3-agenda.borrador.json` revalidado esa mañana. Reemplazar `checkedAt` provisional por la hora real de verificación del 19/10/2026, conservar UTC y la fuente UEFA. En el despliegue protegido, ejecutar vista previa, revisar todos los errores y confirmar usando el token firmado recién emitido. **Esperado:** HTTP 200, `changed=true` la primera vez, 18 partidos, 36 equipos, cero errores; horarios argentinos: cuatro a 13:45 y catorce a 16:00. Repetir vista previa/confirmación: `changed=false`, sin filas duplicadas. **Revertir:** no tocar producción para corregir el archivo; dejar el switch apagado, preparar una nueva vista previa y repetir solo tras revalidar. **NO SEGUIR SI:** la fuente, pares, fecha, horario, conteos o errores no coinciden.

7. **manual — Desplegar habilitación global.** Desplegar el mismo tag con `SPORTS_CHAMPIONS_ENABLED=true`; mantener apagado el switch de cada familia hasta la validación individual. **Esperado:** `/api/sports/champions/switch` informa `effective:false` para familias no activadas; River/UFC siguen iguales. **Revertir:** desplegar de nuevo con la variable en `false`. **NO SEGUIR SI:** alguna familia aparece activa sin autorización, o el apagado no bloquea lecturas y escrituras.

8. **manual — Retirar el acceso temporal.** Eliminar el despliegue temporal y cualquier contraseña, excepción de acceso o alias que se creó para él. Abrir su URL en una sesión sin autenticar y comprobar que devuelve 404/410 o la pantalla de acceso denegado; comprobar también que el alias temporal ya no resuelve al despliegue. **Esperado:** no hay ruta pública al entorno temporal. **Revertir:** no volver a abrirlo públicamente; si hace falta repetir la importación, recrear protección limitada y retirar de nuevo. **NO SEGUIR SI:** el acceso temporal sigue disponible para usuarios no autorizados.

9. **manual — Prueba de privacidad y activación familiar.** Con autorización familiar, encender el switch de esa familia. Un integrante A guarda un pronóstico antes del inicio. En otra sesión, un segundo usuario que sea administrador consulta el mismo partido: su `ownChoice` debe ser `null` y `choices` debe ser `[]`; no debe aparecer conteo de votos ni en la tabla, vista previa, importación, auditoría o logs. El administrador puede guardar su propio pronóstico sin ver el de A. Borrar el pronóstico de prueba de A antes del cierre. **Esperado:** ambas sesiones reciben el mismo esquema de respuesta y solo la elección propia; la familia muestra Jornada 3 y el hilo único. **Revertir:** apagar el switch familiar y eliminar el pronóstico de prueba mediante la acción autorizada. **NO SEGUIR SI:** el administrador ve cualquier elección ajena antes del cierre o falla el aislamiento por familia.

10. **manual — Prueba de apagado operativo.** Apagar el switch familiar desde la interfaz administrativa. Comprobar que termina después de las escrituras autorizadas, que todos los endpoints Champions —incluidas rutas genéricas, comentarios, importadores, pronósticos y resultados— bloquean lecturas y escrituras, y que River/UFC continúan operativos. Confirmar que equipos, partidos, pronósticos, resultados y comentarios Champions siguen almacenados. **Esperado:** `effective:false`, cero acceso Champions y datos conservados. Dejar la familia apagada hasta la apertura aprobada. **Revertir:** no borra datos; para volver a abrir, encender el switch solo con aprobación operativa. **NO SEGUIR SI:** queda alguna escritura Champions autorizada al confirmarse el apagado, se borra información o cambia River/UFC.

**Regla del corte:** si revalidación, importación, privacidad o apagado no quedan verificados antes del 19/10/2026 18:00 (Argentina), no abrir Jornada 3; mover el estreno a Jornada 4.
